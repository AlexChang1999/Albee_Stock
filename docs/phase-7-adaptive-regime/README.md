## 〇、這份藍圖的來源（使用者的願景，原話）

> 「平台能根據股市漲跌、交易量、特別網路訊息（聯準會 / 總統發言，精準抓住演講時間、讀內容推測漲跌、給意見）。
> 並透過不斷的二分法，找出該時段合適的策略——像是『A 股交易量變很大、卻沒什麼漲幅』，根據許多因素推斷出
> 此時該用 C 策略、勝率多少、可投多少 %、遇到什麼情境賣出 / 再買入。這種方法叫什麼？做得到嗎？」

**答案：做得到的部分有正式名稱、也是真實技術；但要把「能做的」與「retail 夢碎的」分清楚。**

## 壹、把願景拆成三塊，各有正式名稱

| 區塊 | 願景描述 | 正式名稱 |
|------|----------|----------|
| **區塊 1** | 讀新聞 / 演講 → 推測漲跌 | **事件驅動交易（Event-Driven Trading）** + **NLP 情緒分析**；聯準會這套叫 **Fed-watching**；靠**經濟事件日曆** |
| **區塊 2** | 「不斷二分法」找出此時該用哪個策略 | **市場狀態辨識（Market Regime Detection / Regime Switching）** + **決策樹（Decision Tree）/ 隨機森林 / XGBoost**；上層叫 **元策略 / 策略選擇（Meta-Strategy / Strategy Selection）** |
| **區塊 3** | 勝率多少、投多少 %、何時賣 / 再買 | **凱利公式（Kelly Criterion）** 部位規模 + **元標籤（Meta-Labeling，López de Prado）** |

> 合起來就是：**「事件驅動訊號 + 市場狀態感知的自適應策略選擇 + 機率化部位管理」**。
> 這是一套有完整文獻的東西，不是憑空亂想。

## 貳、可行性誠實評估（把「能做的」與「夢碎的」分開）

| 區塊 | 可行性 | 誠實評估 |
|------|--------|----------|
| **區塊 2（狀態→選策略）** | ✅ 最可行 | 真正屬於 retail、做得起來的一塊。我們已有 8 策略 + 每策略回測 EV，加一層「依特徵挑策略」是合理擴充。screener 已在算的 `volume_ratio` 就是第一個狀態特徵。 |
| **區塊 3（凱利部位）** | ✅ 可行但要小心 | 凱利公式簡單，但**全凱利極度激進、一次重壓會爆**，務必用**分數凱利**（¼~½）。我們已算出 win_rate / EV，接得上。 |
| **區塊 1（讀演講猜漲跌）** | ⚠️ 最難、最易夢碎 | **不是技術假，是贏不了。** 見下方。 |

**為什麼區塊 1 是夢碎重災區（務必認清）：**
1. **市場有效率**：聯準會排程內容，華爾街在**毫秒**內消化、價格瞬間反映。我們用日線 + 本機 Llama，讀完行情早走完——**速度路線 retail 完全沒得玩**。
2. **LLM 沒有預測力**：它能總結「偏鷹派」，但「鷹派→一定跌」根本不成立（常利空出盡反漲）。把文字轉成可靠的「P(漲)」是未被證實的事。
3. **資料地獄**：驗證「讀新聞能不能賺」要用**當時時間點（point-in-time）的新聞**回測，否則就是後見之明騙自己。這種資料貴、難、極易洩漏未來。

> **結論：我們能爭取的優勢在區塊 2+3（紀律化的狀態感知 + 風險管理），不在區塊 1（比市場快 / 會讀新聞）。**
> 區塊 1 永遠只能當「輔助過濾器」（像現在的情緒層），**絕不能當主要進場依據**。

## 參、目標架構（自適應決策流）

```
            ┌──────────────── 狀態感知層（Phase 7 新增）────────────────┐
 K 線/量價 ─►│ 1. 特徵工程（波動率/趨勢強度/量價背離/量比…）              │
            │ 2. 狀態分類器（決策樹 → 趨勢/盤整/爆量滯漲/高波動…）       │
            └───────────────────────────┬──────────────────────────────┘
                                        ▼
            ┌──────────────── 自適應策略選擇（區塊 2）─────────────────┐
            │ 3. 狀態 → 候選策略對應（每個狀態歷史上哪個策略 OOS EV 最佳）│
            └───────────────────────────┬──────────────────────────────┘
                                        ▼
            ┌──────────────── 機率化下注（區塊 3）─────────────────────┐
            │ 4. 分數凱利部位（用 OOS 勝率/賠率 → 投多少 %）             │
            │ 5. meta-labeling（二級模型：這個訊號值不值得下、下多重）    │
            └───────────────────────────┬──────────────────────────────┘
                                        ▼
            ┌──────────────── 事件過濾（區塊 1，輔助）─────────────────┐
            │ 6. 事件日曆 + LLM 情緒當「否決閘」，不當進場主力           │
            └───────────────────────────┬──────────────────────────────┘
                                        ▼
                      既有執行層（Phase 6 後的 bot_manager）
                      風控出場 + 決策審計 + 雙閘安全閥
```

橫跨全部的鐵律：**[步驟 7 防過擬合驗證框架](step-07-anti-overfitting-validation.md)**——加 ML 會讓過擬合風險倍增，沒有嚴謹的時序交叉驗證，這整套就是「用更複雜的方法更精緻地騙自己」。

## 肆、為什麼 Phase 7 必須等 Phase 6 先做完（不可跳過）

你想加的「狀態→選策略→算勝率→定部位」，**完全依賴回測算出來的勝率和 EV 是真的**。
但 Phase 6 之前的回測是**零成本、零滑價、樣本內過擬合**（見 [Phase 6 P1~P3](../phase-6/README.md)）。

> **如果地基的勝率是假的，你在上面蓋的「凱利部位 + meta-labeling」只會把假數字放大成真虧損。**
> 加越多聰明的層，過擬合越嚴重。**先有誠實的 OOS EV，狀態感知層才有意義。**

依賴關係：
- 步驟 3/4/5 直接吃 Phase 6 [步驟 4](../phase-6/step-04-out-of-sample-validation.md) 的 **OOS EV / 勝率**。
- 整個 Phase 7 的驗證沿用並強化 Phase 6 的「樣本外」精神。
- 部位 / 熔斷與 Phase 6 [步驟 5](../phase-6/step-05-capital-guard.md) / [步驟 9](../phase-6/step-09-circuit-breaker.md) 的資金守門共存。

## 陸、明確界線（避免把願景做成過度工程）

- **不追求「比市場快 / 比市場會讀新聞」**——區塊 1 永遠是輔助過濾，不是主進場。
- **不上強化學習（RL）做端到端交易策略**——RL 在交易上極易過擬合、極難驗證，現階段不碰。
- **每加一層都要先證明它在 OOS 上真的加分**，加不了分就砍掉（延續「不要 vibe slop」原則）。
- **Phase 7 全程仍是 Paper + 雙閘安全閥**，與 Phase 6 同一套鐵則。
- 日內 / 即時資料、付費新聞 API 是區塊 1 的硬限制，列為「需要時才升級」，不在前期。
