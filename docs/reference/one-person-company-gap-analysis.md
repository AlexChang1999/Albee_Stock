# 一人公司缺口分析（2026-06）

> **是什麼**：把使用者的「一人公司」願景（機器人自動抓策略、抓總經數據、回測、人審核、
> Paper 驗證後上真錢，全自動進出場 + 止盈止損 + 決策記錄）對照專案現況（CHANGELOG / README，
> 截至 Phase 11 + Backlog A/B/C 收尾）做的缺口盤點。
>
> **結論先講**：管線機制已蓋八成。真正的缺口集中在兩端——
> **前置進料沒通電**（蒐集員沒料吃、watchlist 手動）與
> **上線後維運**（止損掛本機、無存活監控、有晉升沒降級）。
>
> **定位**：概念盤點文件，純分析、無程式變更。要排實作時，把選定項目寫進

## 第二部分：前置進料缺口（A~E）

機制都蓋好了，但**多數沒通電**——這是前置面最大的盲點。

### A. 市場蒐集員沒料吃
`COLLECTOR_INTERVAL_MIN=0`（關）且 `COLLECTOR_RSS_FEEDS` 沒設，收件匣是空的。
**通電條件**：找 3~5 個實際策略來源 RSS（例：Quantocracy、量化部落格、券商研究）填進
`.env`、開掃描間隔。守 robots / 節流（程式已內建）。

### B. 「策略文字 → 可回測程式」是人工斷層（一人公司最大瓶頸）
蒐集員只收「策略描述文字」；要變成 `backend/strategies/*.py` 仍靠人配
strategy-builder skill 手寫。收 100 篇文章，一個人寫得完幾個策略？
現有的半自動只到「LLM 草擬既有策略的參數組合」（`POST /knowledge/propose`）；
**全新邏輯**的策略沒有自動轉換管線。短期務實做法：把收件匣當「靈感策展」用
（triage 後挑少數值得寫的），別期待全自動。

### C. watchlist 是手動的
掃描/海選範圍靠人填，沒有「自動選股 universe」（如：流動性 / 市值 / 價格門檻
自動產生候選池並定期更新）。等於機器人只看你指定的幾檔——願景是「自動發現機會」，
現況是「在你給的範圍內自動發現機會」。

### D. 總經數據已通電，但「怎麼用」剛被否決
FRED 真資料驗證結果：macro overlay 煞車層 OOS **worth=False（207 folds、Δ=-101.68）**，
已依「真資料下無 OOS 加分就砍」鐵律移除。資料層（`macro_data` / `fred_client` /
`routers/macro.py`）保留。**當下定位：觀測報表**，別急著再接回交易邏輯；
若要再嘗試，必須走同一條 `layer_validation` OOS 驗證才能留。

### E. 政治專討員需鏡像頻道
Discord bot 只能讀「它所在的頻道」，要先建「同步川普貼文的鏡像頻道」才有料；
`POLITICAL_ENABLED` 預設關（關時一律放行、不影響下單）。

## 第三部分：上線後維運缺口（1~9，依危險程度排）

這是願景裡**完全沒想到**的一塊：策略上線之後，誰盯著它？

### 1. 止損掛在本機輪詢、不在券商端 ⚠️ 最危險
現況止盈/止損/追蹤止損是「Bot 每輪檢查持倉再決定出場」——跑在你的電腦上。
電腦當機、Windows 自動更新重開、斷網 → **止損失效、持倉裸奔**。
修法方向：下單改用 Alpaca 原生 bracket / stop order，把止損單**託管在券商伺服器**，
本機斷電也照樣執行。追蹤止損可用 Alpaca trailing stop order。
（注意：改動會碰 `alpaca_client.submit_market_order` 與回測語意對齊，須守「回測=實盤」鐵則。）

### 2. 無存活監控（dead-man switch）
有開機自啟，但系統死了你不會知道。一人公司沒有同事幫你發現。
需要：每日心跳通知（「我還活著，持倉 X 檔、今日決策 N 筆」）+
「超過 N 小時沒心跳」的外部警報（心跳發送方掛了，本機警報也跟著掛——警報要在系統外側）。

### 3. 有晉升、沒降級
董事會核准頁只管「上」（paper → live），沒人管「下」。
策略上線後衰退（市場狀態變了）誰關掉它？需要自動降級：
表現連續低於門檻（如 OOS 預期 EV 的某折扣）→ 自動停 Bot + 通知，人再決定砍或調。

### 4. 回測 EV vs 實跑 EV 沒有自動對帳（tracking error）
「回測=實盤」鐵則守得很好（同資料路徑/含成本/隔日成交/OOS），但策略真的跑起來後，
沒有報表自動比對「回測說 EV 91 vs Paper 實跑 EV 多少」。
tracking error 拉開 = 策略走鐘或回測假設失真，要警報。這也是缺口 3（降級）的判斷依據。

### 5. 部位對帳（reconcile）
DB 記的持倉 vs Alpaca 實際持倉可能漂移（重啟漏單、部分成交、人手動下單）。
需開機時 + 定時 reconcile，不一致就警報、以券商端為準。

### 6. SQLite 單檔沒備份
交易歷史、決策審計、回測歷史、知識庫全在一台 PC 的一個檔。硬碟壞 = 公司資產歸零。
需定期備份（雲端或第二顆碟；SQLite 可用 `VACUUM INTO` 或檔案複製於停機窗口）。

### 7. 組合相關性 / 總曝險上限
回撤熔斷（`circuit_breaker`）與購買力守門（`capital`）有了，
但 10 個 Bot 全做多美國科技股 = 其實只下了一注。缺：總曝險上限、同產業/同方向集中度檢查。

### 8. 法規稅務（台灣人投資美股）
- 股息 30% 預扣（非美國人）；券商年度出 1042-S。
- **PDT 規則**：帳戶 < $25,000 美元時，5 個交易日內當沖 ≤ 3 次，超過被鎖 90 天——
  自動交易**很容易誤觸**（同日買進又被止損賣出就算一次當沖）。真錢前要嘛資金 ≥ $25k，
  要嘛在下單邏輯加當沖計數閘。
- 台灣端海外所得申報（基本所得額）。

### 9. 免費資料源品質閘
Alpaca 免費版（IEX）/ yfinance 有延遲、缺漏、splits 調整問題。
爛資料餵進策略目前不會有警報。需基本品質檢查（缺 bar、價格跳變、零成交量連續出現 → 警報 + 暫停該標的）。

## 第五部分：二次盤點補充（前置 F~H + 與大戶比拚的誠實定位）

> 針對「前置作業機器人還漏什麼」與「判斷情勢需要複雜運算、要跟大戶比」兩個擔心的補充。

### F. 財報 / 總經事件日曆沒接（前置面最該補的一塊）
經查 `services/event_risk.py`：煞車**只吃「情緒分數」**（AI 海選的 LLM 情緒、政治員判讀），
**沒有任何真實事件日曆資料源**——系統不知道「下週四 AAPL 發財報」「明天 FOMC」。
日線策略抱股穿越財報日 = 最大的單日跳空風險，止損擋不住跳空。
- 來源便宜：yfinance 有財報日期、FRED 發布日曆固定、Alpaca 有交易日曆。
- **事件「日期」是 point-in-time 乾淨資料**（公告日期確定、無情緒判讀模糊），
  比新聞情緒可誠實回測得多——這正是 Phase 7 把 event 層標 non-verifiable 的反面：
  「何時有事件」可驗證，「事件導致漲跌」不可驗證。只做「財報前 N 天不開新倉/縮部位」
  這種煞車，走 `layer_validation` OOS 驗證決定去留。
- 這是「根據情報判斷情勢」**最便宜、最可驗證**的一塊，優先於任何花俏模型。

### G. 倖存者偏差（watchlist 擴大後會變嚴重）
回測 universe 只有「現在還活著」的股票——下市/被併的看不到 → EV 系統性高估。
現在 watchlist 小（大型股）影響有限；做缺口 C（watchlist 自動化）擴大範圍後必須正視
（免費資料源幾乎都不含下市股，誠實做法：至少在文件與報表標註此偏差）。

### H. 單一時間框架（日線）的止損落差
波動大的真實含義：盤中可能先打到止損再收回，日線回測看不到盤中路徑。
回測的止損判定與實盤輪詢/券商端止損的觸發時點有結構性落差。
不必急著上分鐘線（資料成本/複雜度大增），但要**知道回測止損是樂觀估計**，
Paper 階段拿實際成交 vs 回測假設對帳（呼應缺口 4 tracking error）。

### 與大戶比拚的誠實定位（重要心法，省你走彎路）

**別比的仗（必輸，零例外）**：速度（HFT 機房 colocation）、算力、付費 tick 級資料、
博士研究團隊。散戶在這些戰場沒有任何勝算，投入越多虧越多。

**散戶的結構性優勢（大戶做不到的）**：
- **容量小**：資金小到大戶吃不下的策略/小標的，你進得去（大戶下單會把價格打跑）。
- **沒有贖回壓力**：可以空手等三個月，基金經理不行（客戶會贖回）。
- **不用交季報**：能忍短期難看、換長期 EV。

**「複雜公式」的真相——你自己的 repo 已親身證明**：
Phase 7 的 adaptive 選策略、kelly 凱利部位，Phase 11 的 macro overlay，
**全在 OOS 真資料驗證被砍**（macro Δ=-101.68）；活下來的只有 meta-labeling 一層。
公式越複雜 = 可 fit 的自由度越多 = 過擬合面積越大。
大戶的優勢從來不是公式長度，是**資料品質與執行成本**。

**該投資的「複雜度」方向**（依報酬率排）：
1. 執行成本與風控（券商端止損、事件迴避 F、降級機制）——直接省錢。
2. 驗證紀律（OOS / walk-forward，已有且運作中）——防止自欺。
3. 預測模型——排最後，且每加一層都過 `layer_validation` 才留。

**真正的對手不是大戶**：是交易成本、過擬合、和「自己手癢改參數」。
這三個贏了，散戶賽道就有正 EV 空間。
