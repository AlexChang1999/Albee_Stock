# Albee Terminal — AI 驅動量化交易終端機需求與架構藍圖

> **文件狀態**：規劃中 (Draft)
> **目標**：將現有的「CRUD 表單式後台」升級為「AI 驅動、視覺化看盤、無摩擦部署」的專業量化交易工作站，並維持零成本的本機運行優勢。

---

## 壹、核心需求 (Requirements)

本階段重構旨在解決現有介面過於僵化、難以同時監控多檔股票，且高度依賴手動輸入參數的痛點。

### 1. 雙軌 AI 交易模式 (Dual-Track AI System)
系統需提供兩種由本機 Ollama 驅動的自動化決策工作流：
* **模式 A（輔助駕駛 / 綠燈模式）：** 
  * AI 每日盤前掃描市場，結合訊息面（新聞/財報）與交易量，計算出多組策略配置。
  * 前端獨立出「AI 策略探勘中心」分頁，以卡片形式展示高期望值（EV > 0）的建議清單。
  * 使用者檢閱後，點擊「一鍵部署 (Deploy)」按鈕，系統自動建立 Bot 並掛載排程。
* **模式 B（自動駕駛 / 紅燈模式）：**
  * 在後端設立「全局自動化規則（Global Automation Rules）」。
  * 當 AI 掃描出的策略 EV 值超過特定閾值（如 EV > 150 且勝率 > 55%），系統無需人工確認，自動配置資金並建立 Bot 實盤/模擬運行。

### 2. 專業級多視角圖表 (Professional Interactive Charting)
廢除現有的 TradingView Widget `<iframe>`，改用資料雙向綁定的原生圖表套件。
* **多螢幕監控：** K 線圖分頁支援網格佈局（例如 2x2 或是自訂分割），可同時即時監控多檔服役中 Bot 的標的。
* **水位線自動繪製：** 系統必須能讀取 Bot 的資料庫狀態，並在圖表上自動畫出：
  * **進場均價線**（白色/灰色虛線）
  * **靜態止損線**（紅色實線）
  * **動態追蹤止盈線**（綠色實線，需隨價格創高自動上移）
* **視覺化操作（未來擴充）：** 支援在圖表上直接拖曳水平線，連動更新後端資料庫的風控 `take_profit_pct` 等參數。

### 3. 無摩擦的 UI/UX 體驗 (Frictionless UI/UX)
* **版面重構：** 主儀表板（Dashboard）移除佔版面的「建立 Bot」表單，改為純粹的監控中心（上方總體損益與 AI 市場燈號，下方為服役中的 Bot 狀態卡片）。
* **視覺升級：** 捨棄預設的亮色系背景，全面改用**深藍色 (Deep Blue)** 為基底的主題風格。這不僅提供更具沉浸感的專業氛圍，也能讓獲利（青綠色）、虧損（洋紅色）等數據指標，以及圖表上的風控水位線更加清晰跳脫，減輕長時間盯盤的視覺疲勞。

## 貳、系統思路與架構設計 (Design Rationale & "Why")

這裡記錄各項決策背後的設計考量，確保未來的技術實作不偏離初衷。

### 為什麼要設計「雙軌 AI 模式」？
* **思路：** 完全信任 AI 直接下真錢的風險極高，但手動一檔一檔看財報跟交易量又失去自動化的意義。
* **解決方案：** 「模式 A」是為了建立人機互信。讓系統幫你處理最繁瑣的「海選、回測、算 EV」階段，把最終決策權（Deploy）留給你。當你發現系統連續一個月推薦的策略都穩定獲利，再將該條件寫入「模式 B」，實現循序漸進的自動化。

### 為什麼要替換掉 TradingView Widget？
* **思路：** 現有的 Widget 就像是在網頁裡開了一個「別人的視窗」，React 程式碼無法輕易介入畫線，也無法將後端計算出的追蹤止損點同步顯示在上面。
* **解決方案：** 引入 `lightweight-charts`。它允許將後端 WebSocket 傳來的即時報價與資料庫裡的風控參數，轉化為圖表上的動態水平線，真正做到「看到哪裡，保護就設在哪裡」。

### 為什麼要改為深藍色主題並移除建立表單？
* **思路：** 在 AI 驅動的架構中，Bot 應由 AI 藍圖轉化，而非人工手填。且金融交易系統需要讓使用者保持冷靜與高度專注。
* **解決方案：** 將主儀表板純粹化，打造為「監控中心」。深藍色系能完美契合科技感與數據密集型的介面，讓關鍵的發光圖表與 AI 決策卡片成為視覺焦點，擺脫傳統 CRUD 後台的框架。

## 參、成本與算力考量 (Cost & Compute Architecture)

本專案的核心優勢在於**「完全免費的零成本運行」**與**「隱私保護」**，但在引入 AI 海選與批次運算時，必須針對硬體算力進行架構優化。

### 1. 零成本技術堆疊 (Zero-Cost Stack)
* **AI 核心：** 透過本機 Ollama 運行開源大型語言模型（如 Llama 3 8B），並透過 `LLM_ALLOW_CLOUD=false` 安全閥將資料鎖在本機，無任何 API Token 費用。
* **資料與交易：** 使用 yfinance 獲取歷史與基本面資料，搭配 Alpaca Paper Trading 進行模擬驗證，不需訂閱高價金融 API 即可建構完整的回測與交易循環。

### 2. 算力優化策略 (Compute Optimization)
為避免盤前 AI 批次掃描癱瘓本機算力，後端必須實作**「漏斗式篩選（Funnel Filtering）」**：
* **第一層（低算力消耗）：** 優先使用 Python / Pandas 進行技術面與交易量篩選（如過濾出 `Volume > MA(20) * 2.5` 的標的）。
* **第二層（高算力消耗）：** 僅將第一層篩選出的小部分標的（約 5~10 檔）之新聞與財報摘要，交由本機 Ollama 進行情緒打分。

### 3. 未來擴展性 (Future Scalability)
系統保留無縫切換付費升級的彈性。若未來需要更強的邏輯推理或毫秒級資料：
* 僅需修改 `.env` 變數開啟 `LLM_ALLOW_CLOUD=true`，即可平滑切換至 OpenAI / Gemini 等雲端模型。
* 可隨時將資料源從 yfinance 切換為 Alpaca 的付費 Data Plan 獲取 Tick Data。

## 肆、階段性實作藍圖 (Phased Implementation Roadmap)

為避免大規模重構導致系統崩潰，建議依下列順序進行：

1. **圖表引擎替換 (Frontend Charting Phase):**
   * 安裝 `lightweight-charts`。
   * 實作單一標的的 K 線圖元件，並成功將測試 Bot 的進場點與止損點繪製為水平線。
   * 實作前端的網格佈局（Grid Layout）以支援多視窗。
2. **AI 推薦資料流 (API & Data Flow Phase):**
   * 實作漏斗式篩選邏輯，後端新增 `GET /ai-recommendations` API。
   * 整合 `yfinance` 批次抓取與 `backtest_engine.py` 批次運算。
   * 前端實作「AI 策略探勘」分頁，將回傳的結果渲染為推薦卡片。
3. **佈局清理與主題切換 (UI Revamp Phase):**
   * 移除 Dashboard 舊有表單。
   * 調整 MUI Theme，套用深藍色系色票。
4. **全自動護欄 (Automation Phase):**
   * 實作「模式 B」，在排程器中加入 EV 閾值判斷，達成條件即自動呼叫 `create_bot` 與下單邏輯。
