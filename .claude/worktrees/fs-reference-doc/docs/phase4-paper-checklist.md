# Phase 4 — Paper 連續實跑驗收清單

> 目的：Phase 4 的風控／監聽／安全閥程式都寫好了，但還沒在真實 Paper 環境
> **連續跑**驗證過。這份清單讓你開幾個 Bot 跑一段時間，逐項打勾確認行為正確，
> 確定穩了再考慮切實盤。
>
> **全程 Paper（模擬）**。`.env` 維持 `ALPACA_BASE_URL=https://paper-api.alpaca.markets`、
> `ALLOW_LIVE_TRADING=false`。

---

## 一、開始前準備

## 三、逐項驗收（每項記「預期 vs 實際」）

### 1. 排程真的在跑

| 檢查項 | 預期結果 | 實際結果 |
|--------|----------|----------|
| 啟動 Bot 後看後端 log | 每隔設定秒數出現該 Bot 的檢查訊息 | |
| 開市時間觀察 | 有抓資料、依策略/風控動作 | |

### 2. 開市判斷

| 檢查項 | 預期結果 | 實際結果 |
|--------|----------|----------|
| 休市時段排程自動跑 | log 顯示「休市中，本次跳過」，不下單 | |
| 手動 `/run`（ignore_market_hours=True） | 休市也能跑、驗證邏輯 | |

### 3. 風控出場（核心，跟錢有關）

| 檢查項 | 預期結果 | 實際結果 |
|--------|----------|----------|
| 持倉後價格跌破止損 | 全部賣出，交易紀錄 reason 標止損 | |
| 持倉後價格漲到止盈 | 全部賣出，reason 標止盈 | |
| 追蹤止損：創新高後回落設定 % | 賣出，reason 標追蹤止損 | |
| 持倉中策略觀望但未觸發風控 | 續抱，不重複下單 | |

### 4. 重啟恢復（這次新修的重點）

| 檢查項 | 預期結果 | 實際結果 |
|--------|----------|----------|
| 有持倉時記下當前 `peak_price`（看 DB 或前端） | 有值 | |
| 重啟後端 | `is_active=True` 的 Bot 自動重新掛回排程 | |
| 重啟後查 `peak_price` | 仍是重啟前的值（不歸零） | |

### 5. 通知

| 檢查項 | 預期結果 | 實際結果 |
|--------|----------|----------|
| 進場/出場時 | 收到通知（LINE 已設定）或 log 降級輸出 | |

### 6. 交易紀錄與績效

| 檢查項 | 預期結果 | 實際結果 |
|--------|----------|----------|
| 每筆買賣 | 交易紀錄分頁出現對應紀錄（價格、股數、reason） | |
| Bot 卡片績效 | 勝率/報酬率/交易次數/最大回撤數字合理 | |

### 7. 多 Bot 並發穩定性

| 檢查項 | 預期結果 | 實際結果 |
|--------|----------|----------|
| 三個 Bot 同時跑數小時 | 不互相卡、沒有 rate limit 報錯 | |
| 單一 Bot 出錯（可故意設錯標的） | 只該 Bot 收到錯誤通知，其他照常 | |

## 四、跑多久才算過關（建議）

- [ ] 至少連續觀察 **3～5 個交易日**
- [ ] 至少各觸發過一次：止損出場、止盈出場、追蹤止損出場
- [ ] 至少經歷一次「後端重啟」並確認排程與 `peak_price` 恢復
- [ ] 期間無未預期的崩潰／重複下單／漏下單

全部打勾後，才進入 `docs/go-live-checklist.md`（實盤切換）的評估。
**Paper 跑得順 ≠ 策略會賺錢**，這份只驗「系統行為正確」，績效是另一回事。
